### **原則間的相互關聯**
1. **SIP 與 OCP**：
   - SIP 幫助將類別拆分為單一職責，讓設計更清晰、更易擴展，為 OCP 奠定基礎。
   - OCP 在 SIP 的基礎上進一步實現「不修改現有類別」即可新增功能。

2. **LSP 與 OCP**：
   - LSP 確保子類行為與父類一致，避免因子類行為破壞導致系統擴展困難，是實現 OCP 的基石。
   - 如果子類違反 LSP，系統會因多型行為不一致而難以擴展。

3. **ISP 與 DIP**：
   - ISP 將接口設計為專注的小接口，減少多餘的依賴，為 DIP 提供基礎。
   - DIP 通過依賴抽象（通常是接口）而不是具體實作，利用 ISP 設計的接口降低耦合度。

4. **OCP 與 DIP**：
   - OCP 通過新增抽象層實現擴展，而 DIP 則保證高層模組僅依賴這些抽象，兩者密切相關。
   - DIP 的實現讓 OCP 的擴展性更加穩固，因為高層模組不需要因低層變化而修改。

5. **SIP 與 LSP**：
   - SIP 幫助類別專注於單一職責，降低子類破壞父類行為契約的可能性，從而更容易實現 LSP。
   - LSP 的正確實現，讓 SIP 設計的類別可以更安全地使用多型。

6. **五原則整體結合**：
   - SIP 幫助拆分職責清晰的類別，確保內部設計簡潔。
   - ISP 設計小而專注的接口，避免接口過大導致類別依賴不必要的方法。
   - LSP 確保子類能安全替代父類，是系統穩定性的核心。
   - OCP 保證系統可以通過新增模組來擴展，而不需修改現有代碼。
   - DIP 確保高層模組依賴於穩定的抽象（接口），減少對具體實作的依賴，提升整體靈活性。
